# ADR-0001: Вибір PostgreSQL як основної реляційної СУБД

Статус: прийнято

## Контекст
Система CoffeeGo вимагає суворого збереження транзакційних даних: фінансових онлайн-оплат, облікових записів користувачів та балансу бонусних балів (нарахування 10% за покупку). Оскільки невідповідність даних або втрата транзакції при оплаті є неприпустимою, обрана СУБД повинна гарантувати відповідність вимогав ACID та мати зручну інтеграцію з Node.js/NestJS.

## Рішення
Обрати **PostgreSQL** (v14+) як основну реляційну базу даних проєкту.

## Наслідки
* **Переваги:**
  * Надійна підтримка ACID-транзакцій для операцій із бонусами та замовленнями.
  * Нативна підтримка типу `JSONB` для збереження кастомних опцій замовлення (додатки, молоко, сиропи).
  * Повна сумісність із ORM (TypeORM / Prisma).
* **Компроміси та обмеження:**
  * Вищі вимоги до оперативної пам'яті порівняно з SQLite.
  * Необхідність адміністрування та налаштування індексів для збереження швидкодії $\le 300\text{ ms}$.
